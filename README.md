# 공 굴리기 게임

이름을 넣고 시작을 누르면 게이트가 열리며 구슬이 떨어져, 뒤로 기울인 나무 판(핀 밭 · 구불구불한 관로 · 스피너 · 갈림길 · 범퍼 · 왕복 블록 · 지름길 · 결승 바퀴)을 굴러 내려가 결승 순서로 당첨자를 뽑는 3D 추첨 게임. 서버 없이 정적 사이트로 배포한다.

설계는 [docs/PLAN.md](docs/PLAN.md), 작업 규칙은 [CLAUDE.md](CLAUDE.md).

## 실행

```
npm install
npm run dev                  # 개발 서버. 폰에서 보려면: npm run dev -- --host
npm run build                # 타입 검사 + 빌드 + gzip 크기
npm run test                 # 단위 테스트
npm run sim -- --seeds 1000  # 헤드리스 시뮬레이션
```

배포: GitHub 저장소에 올리면 `.github/workflows/deploy.yml` 이 master 에 푸시할 때마다 테스트 → 빌드 → GitHub Pages 배포를 한다.
처음 한 번만 저장소 Settings → Pages → Source 를 "GitHub Actions" 로 바꾼다. 주소는 `https://<아이디>.github.io/<저장소 이름>/` 이다(`base: './'` 라 하위 경로에서도 돈다).

## 기능

- 이름 입력: 쉼표·줄바꿈으로 구분, `이름*2` 는 구슬 2개, `이름/3` 은 질량 3배 (최대 30개)
- 셔플(새 시드), 시작, 당첨 기준 1등/꼴찌, 당첨 수 여러 명
- `?seed=8자리16진수&names=...&win=...&n=...&map=...` 링크 공유: 같은 빌드에서 같은 경주가 재생된다
- 추격 카메라: 출발 전에는 고정 시점. 달릴 때는 판 아래쪽에서 올려다보며 선두를 따라가고(구슬이 화면 쪽으로 달려온다), 마지막 구간에서는 낮게 깔려 느리게 돈다
- 미니맵(오른쪽 세로 띠): 판 전체에서 구슬이 어디쯤 왔는지
- 경주 중 배속(1x·1.5x·2x·3x, 기본 1x), 일시정지, 종료. 순위 오버레이, 구슬 이름표
- 움직이는 장애물: 십자 스피너, 큰 풍차, 좌우로 왕복하는 마름모
- 구멍 함정(결승 앞): 붉은 테두리 구멍 여덟 개와 범퍼. 빠지면 세 구간 위(왕복 블록 구간 맨 위)에서 다시 나온다. 구슬 하나당 두 번까지
- 결승(긴 막대): 가파른 깔때기가 좁은 목으로 이어지고, 한쪽 끝을 깔때기 벽에 박은 긴 막대(17cm, 판 폭의 절반 넘게)가 반시계 방향으로 천천히 돌며 목 입구를 훑는다. 시계 방향이면 막대가 구슬을 위쪽 모서리로 몰아 벽을 뚫었다. 1등이 나와도 벽은 그대로고 남은 구슬이 차례로 들어와 순위가 모두 정해진다(안전망: 40초). 구멍 함정부터 결승까지 먼저 온 구슬이 1등을 놓친 판은 60판 중 34판. 벽을 뚫는 구슬은 0개(`node scripts/breach.mjs`)
- 통통 튕기는 구간(중간): 닿으면 튕겨 내는 팝 범퍼 두 줄
- 지름길(결승 앞): 한가운데 좁은 관에 들어가면 곧장 떨어지고, 빗나가면 양옆 선반을 돌아 늦는다
- 갈림길: 가운데 입구 아래에서 좌우로 갈리고, 한쪽은 곧장 떨어지고 다른 쪽은 선반을 돌아 1초쯤 늦는다
- 경주 중 화면을 누르면 2배속(다시 누르면 1배속), 경주가 끝나고 엔터를 누르면 준비 화면으로

## 측정 결과 (낙하판 맵, 구슬 5개, 1배속)

| 기준 | 결과 |
| --- | --- |
| 0단계 물리 검증 3가지 | 통과 (`src/physics/world.test.ts`) |
| 같은 시드 2회 실행 순위 동일 | 통과 (`src/race/race.test.ts`) |
| 빌드 gzip 1.0MB 이하 | 통과: 752 KB |
| 미완주 0개 | 통과: 200시드(구슬 5개), 30시드(구슬 30개)에서 0개 |

| 출발 슬롯별 우승 χ² < 9.49 | 재지 않음. 섞기 단계를 빼서 자리별 유불리가 있다(이름과 자리는 시드로 섞인다) |

공정성은 더 조이지 않기로 했다. 어느 이름이 어느 출발 자리에 설지는 시드로 섞으므로 참가자 사이의 확률은 자리별 유불리와 상관없이 같다.

## 계획서와 달라진 점

1. **지그재그 경사로 코스 → 기울인 낙하판 하나.** 판 위의 2차원 좌표로 벽·블록·핀·스피너·왕복 블록을 놓는다. 판을 기울이는 대신 중력을 기울인다(`tiltDeg`). 판이 cuboid 하나라 이음새가 없다.
2. **유리 덮개 충돌체**가 벽 높이에 있어 구슬이 서로 올라타지 못한다(화면에는 그리지 않는다).
3. **출발 자리는 슬롯 안에서 시드 난수로 흩는다.** 출발 전에 구슬을 튕겨 섞는 단계도 만들었지만(자리별 편향이 사라진다) 보기에 좋지 않아 뺐다.
4. **벽과 장애물 사이 틈은 32mm 이상(또는 구슬이 못 들어가게).** 25mm 틈과 벽에서 10mm 떨어진 핀 옆에 구슬이 끼었다.
5. **진행도는 출발선에서 내려온 거리**(중심선 투영을 없앴다). 판 밖으로 나간 구슬은 출발 칸으로 되돌린다.
6. **끼임 안전망은 판 위 무작위 방향 0.15 m/s**, 구름 저항은 2 cm/s 이상에서만.
7. **나무결·결승선 무늬는 canvas에 그린다**(다운로드 0바이트). wasm 플러그인은 직접 만들었다(`scripts/wasm-plugin.ts`).

## 하지 않은 것

- 리플레이는 시드 링크 방식만 있다. 기기가 달라도 같은 결과가 나오는지는 확인하지 않았고, 궤적 기록 방식은 만들지 않았다.
- 맵 선택, 맵 편집, 화질 선택, 스킬은 화면에서 뺐다(화질은 보통, 스킬은 꺼짐으로 고정).
- 스킬은 부스트 한 종류다.
- 4단계(WebGPU, Rapier 0.21 이전)는 조건부 항목이라 진행하지 않았다.
- 맵은 하나다. 구간 순서만 바꿔 다른 맵을 만들 수 있게 생성기를 짜 두었다(`scripts/make-wood-map.mjs` 의 `sections`).
- 볼링핀과 소용돌이, 녹화 기능은 뺐다.
- 실시간으로 부드럽게 도는지는 정지 화면 몇 장으로만 확인했다.
